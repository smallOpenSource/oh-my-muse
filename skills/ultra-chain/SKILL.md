# ultra-chain — 9단계 풀 체인

## Purpose

단일 작업 목표를 받아 조사부터 공유까지 9단계를 순서대로 실행한다.
각 단계는 해당 스킬의 SKILL.md를 그대로 따르고, 단계 사이에는 승인 게이트를 둔다.
한 단계의 산출물이 다음 단계의 입력이 된다.

## Pipeline

| # | 단계 | 스킬 | 입력 → 산출물 | 게이트 |
|---|---|---|---|---|
| 1 | 자료 조사 | `deep-research` | 목표 → 주장별 확신도·출처 리포트 | - |
| 2 | 모호성 제거 | `deep-interview` | 리포트+목표 → `.omc/specs/` 스펙 | 스펙 확정 승인 |
| 3 | 계획 합의 | `ralplan --deliberate` | 스펙 → Planner·Architect·Critic 3자 합의 계획+ADR (`pending approval`) | 계획 실행 승인 |
| 4 | 계획 시각화 | `loft` | 합의 계획 → 버려도 되는 목업 아티팩트 (클릭 가능 셸 또는 UI 변형 3종) | 목업 승인 |
| 5 | 구현 | `ralph` (+내부 critic) | 승인 계획+목업 → 동작 코드 | - |
| 6 | 독립 QA | `ralph-qa` | 결과+수용 기준 → 3좌석 독립 검증 APPROVE | - |
| 7 | 비주얼 QA | `visual-ralph` | UI 산출물 → Visual Verdict ≥90 | - |
| 8 | 과정 시각화 | (직접 제작) | 단계별 산출물 → 타임라인 HTML | - |
| 9 | 결과 공유 | `artifact` | 최종 산출물 → 아티팩트 카드/파일 | 공유 방식 승인 |

## 단계별 규칙

### 1. deep-research
- SKILL.md 절차 그대로. 적대적 팩트체크, 확신도·출처 표기.
- 산출물은 다음 단계 입력용으로 `research_dir` 형태 보관.

### 2. deep-interview
- 한 번에 한 질문씩. 4개 차원(목표·제약·성공 기준·맥락) 모호도가 임계값 이하까지.
- 인터뷰 중 파일 변경·실행 금지. 스펙 확정은 사용자 승인 후.

### 3. ralplan --deliberate
- `--deliberate` 강제: 프리모템(3개 실패 시나리오)+확장 테스트 계획 포함.
- Planner 초안 → Architect(별도 서브에이전트, 반론 포함) → Critic(또 다른 서브에이전트, Architect 출력 미공유) → 최대 5회 반복.
- 사용자 요구 "셋 이상의 적대적 독립검토": Critic 좌석을 3개 이상 병렬로 두어 합의 루프로 운영한다.
- 최종 계획은 `pending approval` 상태로 저장. 승인 없이는 4단계로 넘어가지 않는다.

### 4. loft (mocking)
- 합의 계획을 버려도 되는 목업으로 시각화해 구현 전 예상 결과물을 확인한다.
- UI 작업: 클릭 가능한 셸 또는 변형 3종. 비-UI 작업: 핵심 흐름을 보여주는 최소 프로토타입.
- 목적은 후속 과정 시간 절감. 목업에 공들이지 않는다.

### 5. ralph (+내부 critic)
- `--critic=critic`의 외부 모델(Codex CLI 등)은 이 환경에서 동작하지 않는다.
- 대신 구현 루프 안에 내부 서브에이전트 critic 좌석을 두어 매 이터레이션 자가 검증한다.
- ralph SKILL.md의 환경 적응 섹션을 따른다.

### 6. ralph-qa
- 정족수 3. 백본 서브에이전트 + 독립 좌석들이 수용 기준 대조로 APPROVE까지 반복.
- 테스트는 가용한 실제 환경에서 직접 실행한다. 이 환경은 Linux 컨테이너이므로,
  Windows/macOS 고유 동작은 해당 OS 박스가 연결되어 있을 때만 실기 검증하고,
  없으면 그 축을 "미검증"으로 명시한다. 검증 안 한 축을 검증했다고 말하지 않는다.

### 7. visual-ralph (visual-qa)
- UI 산출물이 있을 때만 실행. 없으면 건너뛰고 기록에 남긴다.
- Visual Verdict ≥90까지 반복. 사람의 검토 포인트는 최종 승인 한 번으로 최소화한다.

### 8. 과정 시각화
- 1~7단계의 산출물(리포트·스펙·계획·목업·코드·QA 결과·Verdict)을 타임라인 HTML 한 장으로 정리한다.
- 각 단계: 목표, 핵심 결정, 산출물 링크, 소요 개요.

### 9. 결과 공유
- 최종 산출물을 아티팩트로 만든다 (웹이면 `create_web_static`, 파일이면 `create_file`).
- 공개 공유(`artifact.share`)는 사용자 명시 요청 시에만.

## 게이트 정책

- 필수 승인: 2단계 스펙 확정, 3단계 계획 실행, 4단계 목업, 9단계 공개 공유.
- 승인 없이 다음 단계로 넘어가지 않는다. `just do it`류 표현만으로 게이트를 건너뛰지 않는다.
- 단계 실패 시: 해당 단계 스킬의 재시도 규칙을 먼저 적용하고, 3회 실패하면 사용자에게 보고 후 중단.

## Gotchas

- 체인이 길수록 컨텍스트가 커진다. 단계 산출물은 파일로 남기고, 다음 단계에는 파일 경로만 넘긴다.
- `ralph-qa`의 외부 LLM 좌석 부재는 실패가 아니다. 커버리지 사실로 기록한다.
- mocking 단계는 시간을 아끼는 용도다. 목업 품질에 집착하면 체인 취지가 깨진다.
- 6단계 OS 실기 검증은 환경 제약을 정직하게 기록한다.
