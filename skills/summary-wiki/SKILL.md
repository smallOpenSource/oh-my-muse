# summary-wiki: 위키 전량 개조식 digest (sync 검토용)

## Purpose

여러 세션에 걸쳐 쌓인 위키를 `docs/wiki-digest.md` 단일 파일의 개조식 digest로 접는다. 목적은 축약본이 아니라 **사용자가 아는 지식과 위키에 쌓인 내용의 차이를 식별하는 sync 검토 도구**다. 읽기 전용이다. 답변은 한글(기술 토큰·슬러그·경로는 영문).

## When to use

- 위키가 여러 세션에 걸쳐 쌓여, 사용자가 그 안에 무엇이 들었는지 더는 파악하지 못할 때.
- 자리를 비운 사이 에이전트가 기록한 지식을 사람이 따라잡아야 할 때.
- 사용자가 아는 것과 위키에 쌓인 것의 **차이**를 확인하려 할 때(이 스킬의 본래 목적).
- 위키 원본은 그대로 두고 훑을 사본만 필요할 때.

## When NOT to use

- **위키를 정리·압축하려 할 때.** 그건 `compact-wiki`다. digest를 만들다 "이왕 읽는 김에" 중복을 합치기 시작하면 읽기 전용 보장이 깨진다.
- **새 지식을 기록할 때.** `append_wiki` 소관이다.
- **위키를 Obsidian 그래프로 정규화할 때.** `obsidizer` 소관이다.
- **사실 하나를 찾을 때.** grep이 훨씬 싸다. digest는 전수 훑기용이지 검색 인덱스가 아니다.
- **위키가 몇 장 안 될 때.** 원본을 직접 읽는 게 싸다.

## Workflow

### 0. 열거 (추정 금지)

- 위키 디렉터리를 자동 판정한다: `.omc/wiki/` → `omx_wiki/` → `~/memory/` 순으로 존재하는 쪽. Muse 환경의 가장 가까운 대안은 `~/memory/`다.
- **파일을 직접 열거한다.** 예약파일 3종(`index.md`·`log.md`·`environment.md`)은 지식 페이지가 아니므로 제외한다.
- **최대 함정: stale 목록을 열거 근거로 쓰지 마라.** `index.md` 같은 자동 유지 인덱스는 **구조적으로 stale**하다 — 인덱스 갱신이 특정 경로에서만 일어나고, 아무도 staleness를 검사하지 않는다. 실측: 인덱스 목록 16 vs 실제 파일 17 — 한 페이지가 조용히 빠진다. 이 누락은 성공으로 보고되며 이 스킬의 목적(차이 식별)을 정확히 배반한다.

```bash
W=.omc/wiki; [ -d "$W" ] || W=omx_wiki; [ -d "$W" ] || W=~/memory; echo "wiki: $W"
PAGES=$(ls "$W"/*.md | grep -vE '/(index|log|environment)\.md$')
echo "$PAGES" | wc -l                    # 페이지 수 (4단계 검증의 before)
echo "$PAGES" | xargs cksum | cksum      # 위키 지문. 4단계에서 대조한다.
```

- 위키가 없으면 만들지 말고, 요약할 게 없다고 보고하고 끝낸다.
- 페이지 수·총 크기를 먼저 재고(`du -ch`), 크면 `--pages`로 범위를 좁힌다. **좁혔다는 사실을 digest 헤더에 적는다.** 부분 digest를 전수 digest로 보이게 두지 않는다.
- **비용 함정:** 페이지 전량 full read는 컨텍스트를 크게 먹는다. 위키가 커진 뒤에는 digest를 만드는 행위가 **정작 compaction을 유발할 수 있다.** 요약하려다 요약당하는 것이다. 크면 사용자에게 알린 뒤 진행한다.
- 읽지 않은 페이지는 digest에 넣지 않는다. 제목만 보고 항목을 지어내지 않는다.

### 1. 읽기

제목은 프론트매터 `title:`에서, 항목은 본문에서 읽는다. 파일명에서 제목을 추론하지 않는다(슬러그는 64자에서 잘린다 — 잘린 자리는 표시되지 않는다. 예: `...-automation-ceil.md`의 `ceil`이 원래 단어인지 잘린 조각인지 파일명만으로는 알 수 없다).

### 2. 자리 잡기 (docs/ 와 .gitignore)

- 산출물은 타깃 repo의 `docs/wiki-digest.md` 단일 파일이다. `docs/`가 없으면 만든다.
- digest를 tracked 파일로 올리면 감사받은 적 없는 로컬 전용 내용이 공개 repo로 승격된다. `.gitignore`에 `docs/wiki-digest.md`를 추가한다(사용자에게 한 줄로 알리고 진행, 멱등 — 이미 무시되고 있으면 추가하지 않는다: `git check-ignore -q docs/wiki-digest.md && echo "이미 무시됨"`). git repo가 아니면 건너뛴다. 사용자가 커밋을 명시하면 추가하지 않고 4단계 시크릿 스캔을 그때 더더욱 건너뛰지 않는다.

### 3. digest 렌더

단일 파일. 페이지당 한 절. 절마다 개조식 항목.

```markdown
# wiki digest

- 대상: `.omc/wiki/` (Claude/OMC)
- 페이지: 17 (예약파일 3종 제외)
- 열거: 파일 직접 열거 (인덱스 미사용)
- 생성: 2026-09-29

## OMC Wiki Storage Internals And Their Traps
`omc-wiki-storage-internals-and-their-traps` / `.omc/wiki/omc-wiki-storage-internals-and-their-traps.md`

- 프론트매터는 READ 시점에 9-key 로 절단됨
- 슬러그 cap 64자. 파일명에서 제목 복원 불가
- index.md 는 갱신 경로가 제한적이라 구조적으로 stale
- 실측: wiki_list 16 vs wiki_lint 17
```

- 절 헤더의 제목은 프론트매터 `title:` 값 그대로(번역·다듬기 금지).
- 헤더 바로 아래 한 줄에 슬러그와 파일 경로. `[[slug|제목]]` piped 형식 금지.
- 항목은 그 페이지에서 실제로 알 수 있는 것만. "설정 방법을 설명함" 같은 목차 옮기기는 항목이 아니다.
- 페이지 순서는 열거 순서(사전순) 그대로. 중요도 재정렬 금지(판단은 사용자 몫).
- 헤더의 메타(대상·페이지 수·열거 방식·생성일)를 **지우지 마라.** 이 digest가 무엇을 근거로 완전하다고 주장하는지가 거기 있다.
- 개조식: 한 항목 한 사실. 명사·명사형으로 종결. 마침표는 문서 전체에서 한 방식. 중첩은 2단까지. 수식·완충 표현 제거.
- **실패 모드: 불릿만 다는 것.** "개조식으로 써"라는 지시를 받으면 문장 앞에 `- `를 붙이고 끝내기 쉽다 — **그건 개조식이 아니라 줄바꿈**이다. 나쁨: `- 위키 인덱스는 자동으로 유지되는 것처럼 보이지만 실제로는 특정 경로에서만 갱신되기 때문에 오래된 상태로 남아 있을 수 있습니다.`(서술형 종결·한 항목에 세 사실·완충 표현). 좋음: `- wiki_list는 위키가 아니라 index.md를 읽음` / `- index.md 갱신 경로가 제한적이라 구조적으로 stale`. 좋음 쪽은 항목마다 독립적으로 참·거짓을 가릴 수 있어 사용자가 아는 것만 건너뛴다 — **그 건너뛰기가 이 스킬의 값어치 전부다.**

### 4. 검증 (보고 의무)

**시크릿 스캔이 먼저다(게이트).** 통과 전에는 경로를 사용자에게 알리지도, 파일을 옮기지도 마라. 위키는 감사받은 적이 없으므로 **깨끗하다고 가정할 근거가 없다.** 하나라도 나오면 digest에서 지우고 그 자리에 원본 경로만 남긴다.

**개수 대조.** 열거 수와 digest 절 개수가 같아야 한다. 다르면 digest는 미완성이다 — 차액을 찾아 채우기 전까지 보고하지 마라.

```bash
echo "$PAGES" | wc -l              # 열거 수
grep -c '^## ' docs/wiki-digest.md # digest 절 수
```

**위키 무변경 확인.** 0단계 지문과 같아야 한다. **다르면 위키를 건드린 것이다** — 무엇을 바꿨는지 찾아 되돌린다.

```bash
echo "$PAGES" | xargs cksum | cksum  # 0단계 값과 동일해야 한다
```

체크리스트: 절 개수 == 열거 수 / 예약파일 3종이 절로 섞이지 않음 / 절 헤더 제목이 원본 `title:`과 문자열 동일 / 모든 절에 슬러그와 파일 경로 / piped 링크 0 / 서술형 종결 없음·마침표 일관 / 3단 이상 중첩 없음 / 지문 일치.

사용자에게는 파일 경로와 한 줄 요약을 준다: `docs/wiki-digest.md: 17 페이지 요약(예약 3종 제외, 파일 직접 열거). 위키 무변경(지문 일치). 시크릿 스캔 통과.`

## Output Contract

- `docs/wiki-digest.md` 산출 + 4단계 검증 통과 후에만 완료 보고.
- 하나라도 아니오면 고치고 다시 본다. 파일을 썼다는 사실로 완료를 선언하지 않는다.

## Operating Rules

- 읽기 전용이다. 위키에 쓰지 않는다. 태그 정리·링크 보수·오타 수정도 여기서는 금지. 눈에 띄면 보고만 한다.
- digest를 위키 안에 두지 마라. 다음 digest의 입력이 되어 자기를 요약하기 시작한다. 산출물은 언제나 위키 밖(`docs/`).
- 인덱스(stale 가능성 있는 목록)를 열거 근거로 쓰지 마라. 파일을 직접 열거한다.
- `~/memory/` 아래 파일(MEMORY.md·일별 노트)은 read-only다. summary-wiki는 읽기 전용 스킬이라 어긋나지 않지만, 어떤 경우에도 수정하지 않는다.
- compact-wiki(정리·압축)와 섞지 마라. "읽는 김에 합치기"는 읽기 전용 보장을 깨뜨린다.
- 개조식은 관행이지 규정이 아니다. 규정이라고 말하지 마라.
- 한계: 원본의 OMC `wiki_*` MCP 도구와 Codex OMX `omx wiki` CLI는 이 환경에 없다(원본의 "Codex에 `wiki_*` MCP는 없다" 주의 그대로). 파일 직접 열거·파일 read로 우회하므로 실질 비대칭은 디렉터리 경로 하나로 줄어든다.

ARGUMENTS: [--out <파일>] [--pages <slug,...>] [--dir <위키경로>] (없으면 자동 판정된 위키 전량을 `docs/wiki-digest.md`로 요약)
- `--out <파일>`: 산출 경로를 바꾼다. `.gitignore` 게이트와 시크릿 스캔은 그 경로에 그대로 적용한다.
- `--pages <slug,...>`: 지정한 페이지만 요약한다. **범위를 좁혔다는 사실을 digest 헤더에 적는다.** 적지 않으면 부분 digest가 전수 digest로 읽힌다.
- `--dir <위키경로>`: 위키 위치를 직접 지정한다. 자동 판정은 `.omc/wiki/` → `omx_wiki/` → `~/memory/` 순으로 존재하는 쪽이다.
- 어느 경우에도 stale 목록은 쓰지 않는다. 열거는 언제나 파일 직접 열거다.
