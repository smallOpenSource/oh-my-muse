# Map

해야 할 일은 있는데 어떤 스킬이 맡는지 모를 때 아래에서 해당 작업을 찾아 라우트한다. 지도는 라우팅만 한다 — 실행하지 않는다. 라우팅된 스킬의 SKILL.md를 읽고 그 스킬의 지침을 따른다. 수동(manual) 표시가 있는 라우트는 사용자가 직접 채팅으로 호출한다.

## 딜리버리 루프

| 상황 | 스킬 |
|---|---|
| 외부 작업 도착 (이슈, PR, 리포트) | `harbor` |
| 비개발자가 채팅 로그를 요구사항으로 넘김 | `intent` |
| 목적지가 안갯속 — 최초 3개 결정을 아직 말할 수 없음 | `ask-navigator` |
| 막연한 아이디어 — 실행 전에 질문이 먼저 | `deep-interview` |
| 요구사항 명확 — 계획이 필요 | `plan` (다관점 합의: `ralplan`) |
| 승인된 계획 — 사람 체크포인트와 함께 분해·출하 | `launch` |
| 하나의 작업 — 검증 완료까지 끈질기게 | `ralph` (미이식 — `execute`+`verify` 루프 조합으로 대체) |
| 손 떼고 아이디어에서 코드까지 | `autopilot` |
| 조율된 병렬 워커가 필요 | `team` (미이식 — `subagent.spawn` 병렬 실행으로 대체, `execute`의 규모 규칙 참조) |
| 승인된 하나의 작업을 검증된 코드까지 | `execute` |
| 말로 결판 안 나는 디자인 질문 | `loft` |
| 끝난 작업에 판단이 필요 | `omc-review` (원본 스킬명 `review`) |
| 뭔가 완료됐다고 주장함 | `verify` |
| 작업이 PR로 착륙함 | `pr` |
| 이번 실행이 환경에 교훈을 남김 | `refit` — 수동 호출 |

## 진입로 (메인 루프 밖)

| 작업 | 스킬 |
|---|---|
| 버그의 근본 원인이 필요 | `debug` — 경쟁 가설 추적은 `trace` |
| 테스트가 구현을 주도해야 함 | `tdd` |
| 코드베이스가 점점 바꾸기 어려워짐 | `architecture-survey` |
| AI 생성 슬롭 정리 | `ai-slop-cleaner` |
| 열린 질문에 근거 있는 답이 필요 | `research` — 외부 문서는 `external-context` |
| 지식이 세션을 넘어 축적돼야 함 | `remember` (`wiki`는 미이식) |
| 반복 자율 개선 루프 | `self-improve` (미이식) — 목표 원장은 Goals 탭/`user_goal`로 대체 |
| 세션의 전환·결과를 가로질러 재정렬 | `session-flow` — 수동 호출 ("session-flow 해줘") |
| 시각 작업에 판정·다이어그램이 필요 | `visual-verdict`, `diagram` |

## 유틸리티

| 작업 | 스킬 |
|---|---|
| 설치·진단·설정 | `omc-setup`, `omc-doctor`, `configure-notifications` |
| 스킬 자체 관리 | `skill` (로컬), `skillify` (세션에서 추출) |
| 오케스트레이션 상태 조회 | `trace` (추적 레인이기도 함), `graph` (DAG 런타임) |
| 모드 취소 | `cancel` |

## Operating Rules

- 지도는 라우팅만 하고 실행하지 않는다. 각 행은 해당 스킬의 SKILL.md 읽기 + 지침 따르기로 귀결된다. 수동 라우트는 사용자에게 채팅 트리거를 보여주고, 모델이 임의로 호출하지 않는다.
- 두 행이 다 맞으면 딜리버리 루프가 타이브레이크다 — 앞 구간이 먼저다.
- 어떤 행에도 안 맞는 작업은 그 자체가 정보다 — 가장 비슷해 보이는 스킬을 고르지 말고 없다고 솔직히 말한다.
- 미이식 표시가 있는 스킬은 이 라이브러리에 아직 없다. 라우팅할 때 괄호 안의 대체안을 쓴다.
- 이 스킬 자체는 모델이 임의로 호출하지 않는다 — 사용자가 "map 해줘"라고 직접 요청할 때만 사용한다.
