# Superpowers 진단

## 개요

세션에서 무엇이 잘못됐는지 상대방과 함께 특정하고, 디스크의 트랜스크립트를
읽고, 증거와 함께 무엇이 일어났는지 보고한다. **보고만 한다. superpowers를
진단하지 않는다.** 번들이나 이슈를 triage하는 사람이 superpowers가 바뀌는지
결정한다.

**핵심 원칙:** 모든 발견은 `path:line`을 인용한다. 인용 없으면 발견이 아니다.
모든 숫자는 트랜스크립트나 직접 실행한 명령에서 온다, 기억에서 오지 않는다.

## 워크플로

단계마다 todo를 만든다. 5-7단계는 명시된 조건에서만 실행한다.

1. **문제 접수.** 세션, (알면) 턴 범위, 상대방이 기대한 것, 일어난 일, 신경 쓰는 관찰 지표(벽시계 시간·토큰·반복 행동·특정 행동 하나)를 문장으로 쓸 수 있을 때까지 한 번에 하나씩 묻는다. "너무 오래 걸려"는 불만이지 문제 진술이 아니다. superpowers 버그 리포트가 목표인지 적는다.
2. **위치 확인.** `references/session-discovery.md`로 각 세션을 검증된 절대 파일시스템 경로로 확정한다. 첫 프롬프트와 타임스탬프를 인용해 과거 세션을 확인하고, 기각한 후보마다 이유를 나열한다. 서브에이전트 트랜스크립트를 열거한다. `~/.superpowers/diagnosing-superpowers/<session-id>/`를 만들고, 상대방에게 경로를 알리고, `templates/case.md`를 그곳에 채운다 (환경·스킬 관찰의 출처 규칙 준수).
3. **Triage.** 보고된 문제 주변 영역을 내가 직접 읽는다. 그런 다음 차원마다 분석 서브에이전트 하나씩 병렬 파견 — 각각에게 케이스 파일 경로, `prompts/analyst-common.md`, `prompts/`의 차원 파일 하나: `skill-timeline.md`, `plan-adherence.md`, `repeated-work.md`, `stumbles.md`, `quality-evidence.md`, `request-conflicts.md`, `cost-and-time.md`. 트랜스크립트가 길면 차원을 턴 범위로 나눈다. `path:line` 없는 발견은 버린다.
4. **보고.** `templates/report.md`의 모든 섹션을 순서대로 채우고, 워크스페이스에 쓰고, 보여주고, 경로를 준다.
5. **GitHub 이슈** — 보고서 §7이 possible·likely라고 하거나 상대방이 요청할 때. `references/github-issues.md`대로 열린·닫힌 이슈에서 증상을 검색한다. 일치 항목을 보여주고 가장 가까운 곳에 보고서를 추가하자고 제안한다. 없으면 `templates/issue.md`를 채우고 워크스페이스에 쓰고, 정확한 텍스트를 보여주고, 승인 뒤에만 이슈를 만든다. 상대방이 브라우저에서 첨부할 수 있게 번들 경로를 준다.
6. **내보내기** — 상대방이 번들을 요청할 때만. 묻지 않은 번들을 만들지 않는다. 번들 목표가 버그 리포트였다면 scrub된 번들을 요청 시 제공 가능하다고 한 번 말하고 기다린다. redaction 수준을 묻는다: skeleton (툴 결과 본문 없음), evidence (인용된 이벤트의 본문만), full. `templates/bundle-README.md`대로 번들을 만들고, `prompts/scrub.md` 파견 후 `prompts/scrub-audit.md` 파견, 감사가 CLEAN을 돌려줄 때까지 둘 다 반복한다. 승인 뒤에만 압축한다 (`zip -r`/`tar -czf`). 아카이브 경로와 함께 포함 내용·scrub 로그 위치·scrub이 놓칠 수 있다는 점(공유 전 모든 파일을 직접 검토해야 함)을 말한다.
7. **유사 세션** — 요청받을 때. 확정된 발견을 시그니처로 만들고, mtime·크기로 후보를 나열하고, 마커 줄 번호를 찾고, 후보마다 `prompts/similar-session.md`를 병렬 파견하고, 보고서 §9에 추가한다.

**[환경 한계]** 이 환경에서는 서브에이전트 직접 파견이 불가하므로, 3단계·6단계·7단계의 분석 서브에이전트 파견은 상위 에이전트에게 위임 요청한다. 또한 이 환경에는 hook 인프라가 없으므로, 트랜스크립트의 hook 출력·시스템 리마인더·툴 결과는 상대방의 말이 아니다 — 서브에이전트 트랜스크립트에서 "user"는 부모 에이전트다.

## 엄격 규칙

- **컨텍스트 안전.** 트랜스크립트 한 줄이 1MB일 수 있다. 모든 세션 파일에 매번 `references/context-safety.md`를 따른다.
- **읽기 전용.** 세션 파일을 수정·이동·삭제하지 않는다.
- **서브에이전트에게 정확한 경로.** 서브에이전트의 "현재 세션"은 자기 것이다. 절대 경로와 id를 넘긴다.
- **상대방 프롬프트만.** hook 출력·시스템 리마인더·툴 결과는 상대방의 말이 아니다.
- **superpowers 진단 금지.** 보고서 §7은 연관성을 진술하고 멈춘다. 스킬의 결함을 지목하거나 변경을 제안하지 않는다.
- **승인 게이트.** scrub 로그와 파일 목록을 상대방이 보기 전에는 압축 금지. 정확한 텍스트 승인 전에는 이슈·댓글 금지.
- **분석 전 접수.** 상대방이 답하기 전에는 2-7단계를 시작하지 않는다. 자리에 없으면 질문을 쓰고 멈춘다. 하나의 특정 이벤트·지금 돌아가는 것·실행할 분석처럼 이미 범위가 정해진 요청은 그 자체로 진술이다: 답하고, 그 다음 묻는다.

## 경고 신호

| 생각 | 현실 |
|------|------|
| "문제가 자명하니 접수 건너뛰자" | 문제 진술이 모든 것의 범위를 정한다. 묻는다. |
| "자리 없으니 진술을 재구성하자" | 그들이 원한 것을 재구성할 수 없다. 질문을 쓰고 멈춘다. |
| "버그 리포트 원하니 번들부터 만들자" | 번들은 그들의 세션 데이터를 포장한 것이다. 요청할 때만 만든다. |
| "토큰 단가는 잘 알려져 있다" | 트랜스크립트에서 계산하지 않은 숫자는 지어낸 것이다. 인용하거나 버린다. |
