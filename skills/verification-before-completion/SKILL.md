# 완료 전 검증

## 개요

**핵심 원칙:** 항상 증거가 주장보다 먼저.

**이 규칙의 문자를 어기는 것은 정신을 어기는 것이다.**

## 철칙

```
새 검증 증거 없이 완료 주장 금지
```

이 메시지에서 검증 명령을 실행하지 않았으면 통과한다고 주장할 수 없다.

## 게이트 함수

```
어떤 상태 주장이나 만족 표현 전:

1. 식별: 이 주장을 증명하는 명령은 무엇인가?
2. 실행: 전체 명령을 실행한다 (새로, 완전히)
3. 읽기: 전체 출력, 종료 코드 확인, 실패 수 세기
4. 검증: 출력이 주장을 확인하는가?
   - 아니오: 증거와 함께 실제 상태를 말한다
   - 예오: 증거와 함께 주장을 말한다
5. 그 다음에만: 주장을 한다

하나라도 건너뛰면 검증이 아니라 거짓말이다
```

## 흔한 실패

| 주장 | 요구 | 충분하지 않은 것 |
|------|------|----------------|
| 테스트 통과 | 테스트 명령 출력: 실패 0개 | 이전 실행, "통과하겠지" |
| 린터 깨끗 | 린터 출력: 에러 0개 | 부분 체크, 외삽 |
| 빌드 성공 | 빌드 명령: 종료 0 | 린터 통과, 로그가 좋아 보임 |
| 버그 수정 | 원래 증상 테스트: 통과 | 코드 변경, 고쳤다고 가정 |
| 회귀 테스트 동작 | Red-Green 사이클 검증 | 한 번 통과한 테스트 |
| 에이전트 완료 | VCS diff에 변경 표시 | 에이전트 "성공" 보고 |
| 요구사항 충족 | 한 줄씩 체크리스트 | 테스트 통과 |

## 경고 신호 — 멈춤

- "하겠지", "아마", "같아 보여" 같은 말 사용
- 검증 전 만족 표현 ("좋아요!", "완벽해요!", "끝!" 등)
- 검증 없이 커밋/푸시/PR하려 함
- 에이전트 성공 보고 신뢰
- 부분 검증에 의존
- "이번 한 번만"
- 피곤해서 일을 끝내고 싶음
- **검증 실행 없이 성공을 암시하는 모든 표현**

## 합리화 방지

| 변명 | 현실 |
|------|------|
| "지금 되겠지" | 검증을 실행한다 |
| "자신 있어" | 확신 ≠ 증거 |
| "이번 한 번만" | 예외 없음 |
| "린터 통과했어" | 린터 ≠ 컴파일러 |
| "에이전트가 성공이라 했어" | 독립적으로 검증한다 |
| "피곤해" | 피로 ≠ 변명 |
| "부분 체크면 충분해" | 부분은 아무것도 증명하지 않는다 |
| "다른 말이니 규칙 적용 안 돼" | 문자보다 정신 |

## 핵심 패턴

**테스트:**
```
✅ [테스트 명령 실행] [34/34 통과 확인] "모든 테스트 통과"
❌ "이제 통과하겠지" / "맞아 보여"
```

**회귀 테스트 (TDD Red-Green):**
```
✅ 작성 → 실행 (통과) → 수정 되돌리기 → 실행 (반드시 실패) → 복원 → 실행 (통과)
❌ "회귀 테스트를 썼다" (Red-Green 검증 없이)
```

**빌드:**
```
✅ [빌드 실행] [종료 0 확인] "빌드 통과"
❌ "린터 통과했어" (린터는 컴파일을 확인하지 않는다)
```

**요구사항:**
```
✅ 계획서 다시 읽기 → 체크리스트 만들기 → 각 항목 검증 → 빠짐 또는 완료 보고
❌ "테스트 통과, 단계 완료"
```

**에이전트 위임:**
```
✅ 에이전트 성공 보고 → VCS diff 확인 → 변경 검증 → 실제 상태 보고
❌ 에이전트 보고 신뢰
```

## 적용 시점

**항상, 아래 전:**
- 성공/완료 주장의 모든 변형
- 만족의 모든 표현
- 작업 상태에 대한 긍정적 진술
- 커밋, PR 생성, 태스크 완료
- 다음 태스크로 이동
- 에이전트에게 위임

**적용 대상:**
- 정확한 문구
- 바꿔 말한 표현과 유의어
- 성공의 암시
- 완료/정확성을 시사하는 모든 소통
