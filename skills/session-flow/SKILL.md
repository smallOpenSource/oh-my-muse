# Session Flow

이 대화가 실제로 어떻게 전개됐는지 증거 기반으로 압축한 지도를 만든다. 세션을 옮기거나 압축한 뒤 사용자가 방향을 다시 잡게 하는 용도다. 조언성 요약이지, 플래너·실행기·사용자 작업 목록의 대체품이 아니다.

## Modes

- 인자 없음: 전체 지도를 렌더한다. 이 환경에는 네이티브 Task 도구가 없으므로 **읽기 전용** — 저장됐다고 주장하지 않는다.
- `short`: 목표·현재 단계·사용자에게 필요한 것만 반환한다. 읽기 전용.
- `reset`: 원본의 소유 Task 조회·삭제 로직은 이 환경에 적용 불가 — Task 도구가 없으므로 조회·삭제할 수 없음을 명시하고 종료한다. 새 지도는 렌더하지 않는다.

## Workflow

1. 이 대화의 사용자 메시지와 도구 결과에서 흐름을 재구성한다. **레포 상태만으로는 단계를 증명하지 않는다.** 원래 목표와 명시적 목표 변경·전환·완료된 결과·버려진 경로·사용자 대기 중인 결정을 분리한다.
2. 기록이 뒷받침하면 4~8개의 의미 있는 단계로 만든다. 듬성한 기록을 채우거나 작업을 지어내지 말고 적게 쓴다. 단계마다 결과 하나:
   - `✅` 대화가 뒷받침하는 결과로 완료
   - `▶` 현재 미완료 단계
   - `○` 명시적으로 계획됐으나 미시작 단계
   - `✂` 버려짐 — 버린 이유와 함께
   - `↪` 전환 — 이전 방향과 증거 있는 새 방향 함께
3. 단계마다 압축된 증거 포인터 하나. 대화에 나온 실제 URL·아티팩트 경로가 있으면 쓰고, 없으면 특징적인 짧은 사용자 인용이나 도구 결과를 인용한다. 링크를 지어내거나 추론을 사실처럼 말하지 않는다. 불확실하거나 압축 전 재구성은 `inferred`로 표시한다.
4. 전체 지도는 **최대 15줄**: 단계당 한 줄 + 간결한 목표·`Needs you`·`Next` 줄. 열린 결정은 `Needs you`에 넣고, 없으면 `none`. `Next`는 대화가 뒷받침하는 구체적 다음 행동일 때만 쓴다.

## Output

안정적이고 간결한 형태:

```text
🎯 Goal: <목표 및 증거 있는 변경>
✅ S1 <단계> → <결과> — evidence: <출처 포인터>
↪ S2 <이전 방향> → <새 방향> — evidence: <출처 포인터>
▶ S3 <현재 단계> — evidence: <출처 포인터>
✂ S4 <버린 경로> — <이유> — evidence: <출처 포인터>
⏸ Needs you: <결정 또는 none>
➡ Next: <뒷받침되는 다음 행동 또는 none>
```

해당 없는 예시 행은 생략한다. 대화가 정정을 뒷받침하지 않는 한 단계 순서를 호출마다 안정적으로 유지한다.

## Operating Rules

- 이 스킬은 모델이 임의로 호출하지 않는다 — 사용자가 "session-flow 해줘"라고 직접 요청할 때만 사용한다.
- **한계**: 원본의 네이티브 Task 도구(TaskList/TaskGet/TaskCreate/TaskUpdate)와 OMC continuation hook은 이 환경에 없다. 지도는 렌더만 하고, 영속됐다고 주장하지 않는다. `reset`은 "조회·삭제 불가"를 명시하고 끝낸다.
- 추론은 `inferred`로 표시하고, 증거 없는 단계는 만들지 않는다.
