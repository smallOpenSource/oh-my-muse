# Trace

## Purpose

- 모호하고(ambiguous), 인과적이며(causal), 증거가 많이 필요한(evidence-heavy) 질문에 사용한다. 목표는 관찰된 결과가 **왜** 일어났는지 설명하는 것이지, 바로 고치거나 코드를 다시 쓰는 게 아니다.
- 좋은 진입 사례: 런타임 버그·회귀, 성능/지연/리소스 동작, 아키텍처·프리모템·포스트모템 분석, 실험 결과 추적, 설정/라우팅/오케스트레이션 동작 설명, "이 출력이 주어졌을 때 가능한 원인을 거슬러 올라가기".

## Workflow

### 1. 관찰 재진술과 가설 생성

관찰된 결과("왜" 질문)를 정확히 재진술하고, **의도적으로 서로 다른** 3개의 경쟁 가설을 생성한다. 기본 레인(프롬프트가 더 나은 분할을 강하게 시사하지 않는 한):

1. **코드 경로 / 구현 원인**
2. **설정 / 환경 / 오케스트레이션 원인**
3. **측정 / 아티팩트 / 가정 불일치 원인** — 시스템 결함이 아니라 검증 방법의 결함을 포함한다. 예: 검증 쿼리가 서로 다른 엔티티·테넌트·스트림에 단일 차원 키를 재사용, 비교 필터 형태가 스키마 grain과 불일치, 카탈로그·컬럼명이 런타임 간 이식 가능하다고 열거 없이 가정. 레인 3에서는 에스컬레이션 전에 전제 감사(premise audit): 엔티티 차원을 열거하고, 제로-행/불일치 결과가 시스템 결함이 아니라 한 키를 여러 엔티티에 적용한 검증 방법론 결함인지 먼저 확인한다.

### 2. 병렬 증거 수집

`subagent.spawn`으로 레인당 하나의 tracer 워커를 **병렬** 실행한다 (기본 3개). 역할 프롬프트는 `~/workspace/skills/omc-team/references/agents/tracer.md`를 사용한다. 워커는 **서로 다른** 설명을 추적해야지, 같은 설명을 병렬로 추적하면 안 된다.

각 워커는 해당 레인에 대해 다음을 수행한다:
- 레인 가설을 명시적으로 재진술
- 가설을 **지지하는** 증거 수집
- 가설에 **반대되는** 증거 / 부족한 부분 수집
- 증거 강도 순위 매기기
- 부족한 증거·실패한 예측·남은 불확실성 지적
- 해당 레인의 **critical unknown** 명명
- 레인별 최적 **discriminating probe** (불확실성을 가장 빨리 무너뜨릴 다음 단계) 제안
- 명시적 지시가 없는 한 구현으로 붕괴하지 않기

증거 소스: 관련 코드·테스트·설정·문서·로그·출력·벤치마크 아티팩트, git 히스토리.

### 3. 교차 검증 렌즈

초기 증거 수집 후, 관련 있을 때 리더 가설을 다음 렌즈로 압박 테스트한다:
- **시스템 렌즈** — 큐, 재시도, 백프레셔, 피드백 루프, 상·하류 의존성, 경계 실패, 조정 효과
- **프리모템 렌즈** — 현재 최적 설명이 불완전하거나 틀렸다고 가정. 나중에 추적을 당황시킬 실패 모드는?
- **과학 렌즈** — 대조군, 교란 변수, 측정 편향, 대안 변수, 반증 가능한 예측

### 4. 반박 라운드와 수렴 판정

- 가장 강한 비선두 레인이 현재 선두에 최선의 반박을 제시하게 한다. 선두는 주장(assertion)이 아니라 **증거**로 답해야 한다.
- 반박이 선두를 실질적으로 약화시키면 순위를 다시 매긴다.
- 두 "다른" 가설이 같은 근본 인과 메커니즘으로 축소되면 병합하고 명시한다.
- 두 가설이 여전히 다른 다음 probe를 시사하면, 비슷하게 들려도 분리 유지한다.
- 수렴은 같은 표현을 쓴다고 성립하지 않는다. 같은 근본 인과 메커니즘이거나, 독립 증거 흐름이 같은 설명을 가리킬 때만 수렴이다.

### 5. 리더 종합

종합(concatenate이 아닌 synthesis)으로 최종 답을 반환한다: 관찰 결과 → 순위 매긴 가설 → 가설별 증거 요약 → 반대/부족 증거 → 반박 라운드 → 수렴·분리 노트 → 가장 유력한 설명 → critical unknown → 권장 discriminating probe → (불확실성이 여전히 크면) 추가 추적 레인. 순위 쇼트리스트는 한 설명이 지배적이어도 유지한다.

## Output Contract

- **Observed Result** — 관찰된 것
- **Ranked Hypotheses** — 순위표 (순위 | 가설 | 신뢰도 | 증거 강도 | 선두 이유)
- **Evidence Summary by Hypothesis** / **Evidence Against · Missing Evidence**
- **Rebuttal Round** — 선두에 대한 최선 반박과 선두가 유지/붕괴된 이유
- **Convergence · Separation Notes**
- **Most Likely Explanation**, **Critical Unknown**, **Recommended Discriminating Probe**
- **Additional Trace Lanes** (불확실성이 여전히 클 때만, 선택)

## Operating Rules

### 핵심 추적 계약 (항상 유지)

1. **Observation** — 실제 관찰된 것
2. **Hypotheses** — 경쟁 설명들
3. **Evidence For** — 각 설명을 지지하는 것
4. **Evidence Against / Gaps** — 모순되거나 아직 부족한 것
5. **Current Best Explanation** — 현재 선두 설명
6. **Critical Unknown** — 상위 설명들을 가르는 핵심 미확인 사실
7. **Discriminating Probe** — 불확실성을 가장 빨리 무너뜨릴 다음 단계

다음으로 붕괴 금지: 일반적인 fix-it 코딩 루프, 일반 디버거 요약, 워커 출력 raw 덤프, 증거가 불완전한데 가장한 확신.

### 증거 강도 위계 (강한 순)

1. 통제된 재현 / 직접 실험 / 고유하게 판별적인 아티팩트
2. 출처가 탄탄한 1차 아티팩트 (로그, 메트릭, 설정, git 히스토리, file:line 동작)
3. 같은 설명으로 수렴하는 복수의 독립 소스
4. 단일 소스의 코드 경로·행동 추론
5. 약한 정황 단서 (타이밍, 네이밍, 스택 순서, 과거 버그와의 유사성)
6. 직관 / 유추 / 추측

상위 증거에 모순되는데 하위 티어에만 의존하는 가설은 명시적으로 강등한다.

### 강력 반증 규칙

- 진지한 `/trace` 실행은 반드시 자신의 최애 설명을 **반증**하려 시도해야 한다.
- 각 상위 가설에 대해: 지지 증거 + 반대 증거를 수집하고, 독특한 예측을 명시하고, 무엇이 관찰되면 그 가설과 화해하기 어려운지 명시하고, 차선 대안과 가르는 가장 저렴한 probe를 식별한다.
- 다음 경우 가설을 강등한다: 직접 증거가 모순됨 / 검증 안 된 가정을 추가해야 살아남음 / 라이벌과 구별되는 예측이 없음 / 더 강한 대안이 더 적은 가정으로 같은 사실을 설명함 / 지지가 정황 위주인데 라이벌은 상위 증거 보유 / 반박 라운드에서 패배 / 더 강한 상위 설명으로 수렴.

### 동작 불가 요소와 대안

1. **Claude built-in team mode 없음** — 원본의 팀 모드 오케스트레이션은 이 환경에서 동작하지 않는다. 대안: 리드(스킬 실행 주체)가 `subagent.spawn`으로 tracer 레인을 병렬 실행하고, 반박 라운드와 종합을 리드가 직접 수행한다.
2. **`trace_timeline` / `trace_summary` 도구 없음** — 원본이 언급한 기존 추적 아티팩트 조회 도구는 존재하지 않는다. 대안: 코드·로그·설정·git 히스토리를 직접 조사한다.
3. **외부 모델 불가** — Codex/Gemini 등 외부 모델 워커는 지원하지 않는다. 모든 레인은 Muse 기반 서브에이전트로 실행한다.
4. **추적은 설명만, 수정 금지** — 명시적 지시가 없는 한 구현으로 붕괴하지 않는다.
5. **명령어 흡수**: 원본 `/oh-my-claudecode:trace <관찰>` 슬래시 커맨드는 단순 디스패치 래퍼였으므로, 이 스킬의 채팅 트리거("trace 해줘" 등)로 대체된다. 인자는 채팅으로 전달된 관찰 내용이다.

### 출력 품질 기준

- 증거 기반, 간결하지만 엄밀함
- 성급한 확신에 회의적
- 부족한 증거를 명시
- 다음 행동이 실용적
- 약한 설명이 왜 강등됐는지 명시 (순위만 보여주지 않기)
