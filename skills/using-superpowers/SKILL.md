## 규칙

**관련되거나 요청된 스킬을 모든 응답·행동 전에 호출한다** — 확인 질문·코드베이스 탐색·파일 확인도 그 뒤다. 상황에 맞지 않으면 쓰지 않아도 된다.

**계획 모드 진입 전:** 아직 브레인스토밍하지 않았다면 brainstorming 스킬을 먼저 호출한다.

그런 다음 "[목적]을 위해 [스킬]을 사용합니다"라고 알리고 스킬을 정확히 따른다. 체크리스트가 있으면 항목마다 todo를 만든다.

## 스킬 우선순위

여러 스킬이 적용되면 프로세스 스킬이 먼저 — 접근 방식을 정하고, 그 다음 구현 스킬이 실행한다.

- "X를 만들어 보자" → brainstorming 먼저, 그 다음 구현 스킬
- "이 버그를 고쳐라" → systematic-debugging 먼저, 그 다음 도메인 스킬

## 경고 신호

이런 생각은 멈춤 신호다 — 합리화하고 있다:

| 생각 | 현실 |
|------|------|
| "그냥 단순한 질문이야" | 질문도 작업이다. 스킬을 확인하라. |
| "먼저 맥락이 더 필요해" | 스킬 확인이 확인 질문보다 먼저다. |
| "코드베이스를 먼저 탐색하자" | 탐색 방법은 스킬이 정한다. 먼저 확인하라. |
| "스킬을 기억해" | 스킬은 진화한다. 현재 버전을 읽어라. |
| "정식 스킬까지는 필요 없어" | 스킬이 있으면 쓴다. |
| "일단 이거 하나만 하자" | 행동하기 전에 확인하라. |
| "생산적으로 느껴져" | 무분별한 행동은 시간 낭비다. 스킬이 막아준다. |

## 플랫폼 적응

**이 환경 (Muse):** 아래 도구 매핑으로 스킬의 행동 지시를 해석한다.

| 스킬이 요구하는 행동 | 이 환경의 대응 |
|---------------------|----------------|
| 파일 읽기 | `muse.read` (여러 파일은 여러 번 호출 또는 검색) |
| 새 파일 만들기 | `muse.write` |
| 파일 수정 | `muse.edit` |
| 셸 명령 실행 | `muse.exec` (장시간 작업은 `background: true` + `process` 도구로 추적) |
| 파일 내용 검색 | `muse.exec`의 grep 또는 `muse.read` |
| URL 가져오기 | `browser.open` |
| 웹 검색 | `browser.search` |
| 스킬 호출 | 해당 스킬 디렉토리의 `SKILL.md`를 읽고 지시를 따른다 |
| 서브에이전트 파견 | 상위 에이전트에게 위임 요청 (이 서브에이전트 환경에서는 직접 파견 불가 — 보고서로 권고) |
| todo 추적 ("todo를 만들어라") | `tracking` 도구 또는 마크다운 작업 파일 |
| 사용자에게 질문 | 상위 에이전트를 통해 전달 |

원본의 하네스별 레퍼런스(`references/claude-code-tools.md` 등)는 이 환경에 맞지 않으므로, 위 표를 우선 적용한다.

**[환경 한계]** 이 환경에는 hook 인프라가 없다. 스킬이 요구하는 훅 기반 강제(자동 트리거·검증 훅)는 지원하지 않는다 — 지시 내용을 수동 절차로 수행한다.

## 사용자 지시

사용자 지시 (CLAUDE.md, AGENTS.md, 직접 요청 등)가 스킬보다 우선하고, 스킬이 기본 동작보다 우선한다. 상대방이 명시적으로 건너뛰라고 한 경우에만 스킬 워크플로·지시를 생략한다.
