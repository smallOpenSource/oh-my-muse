## Purpose

모호한 "동작할 것 같다" 주장을 구체적인 증거로 바꾼다. 변경을 완료라고 말하기 전에, 증명해야 할 정확한 동작을 식별하고 가능한 가장 좁은 직접 검증으로 확인한다.

## Workflow

1. 증명해야 할 정확한 동작을 식별한다.
2. 기존 테스트를 우선 사용한다.
3. 커버리지가 없으면 가장 좁은 직접 검증 명령(빌드, 타입체크, 단일 스크립트 실행 등)을 돌린다.
4. 자동 검증이 부족하면 수동 검증 단계를 서술하고, 관찰 가능한 구체 증거를 모은다.
5. 실제로 검증된 것만 보고한다.
6. 사용자 인자($ARGUMENTS)가 있으면 검증 대상으로 삼는다. (commands/verify.md 트리거: `/oh-my-claudecode:verify` 호환 명령의 전체 스킬 디스패치를 이 Workflow로 수행한다.)

## Output Contract

- 보고 항목: 검증한 것, 실행한 명령/테스트, 통과한 것, 실패하거나 미검증인 것.
- 증거 없이 완료라고 말하지 않는다. 실패한 검사는 실패를 명확히 포함한다.
- 현실적인 검증 경로가 없으면 없는 대로 명시하고 허세를 부리지 않는다.
- 시끄러운 로그보다 간결한 증거 요약을 선호한다.

## Operating Rules

- **검증 순서**: 기존 테스트 → 타입체크/빌드 → 좁은 직접 명령 검사 → 수동/인터랙티브 검증.
- **외부 의존 불가**: 원문의 Claude Code 플러그인 경로(`CLAUDE_PLUGIN_ROOT` 하 SKILL.md 디스패치)는 이 환경에 적용되지 않는다. 이 스킬 본문이 곧 전체 지침이며, `commands/verify.md`의 디스패치 기능은 위 Workflow 6단계에 흡수된다.
- **슬래시 명령어 치환**: 원문의 `/oh-my-claudecode:verify` 트리거는 "verify 해줘" 같은 채팅 요청으로 받는다.
