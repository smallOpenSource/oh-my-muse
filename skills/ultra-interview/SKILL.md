# ultra-interview: 리서치 선행 인터뷰 (모호성 3% 이하까지)

## Purpose

요구사항 확정 인터뷰다. 종료 기준이 **모호성 3% 이하**(이산 체크리스트 위에서 센다)이고, **리서치를 질문보다 먼저** 돌려 사람에게 묻는 질문을 최소화한다. 이 둘을 빼면 이 스킬은 존재 이유가 없다. 답변은 한글(기술 토큰·경로·명령은 영문).

**런타임:** 이 스킬은 **자체 루브릭을 소유**한다. 런타임 네이티브 인터뷰의 채점을 물려받지 않는다 — 산식이 다르기 때문이다. 다른 인터뷰의 점수와 나란히 적을 때는 런타임 라벨을 단다. 라벨 없는 숫자는 비교 불가다. 리서치는 런타임이 주는 검색·조회 수단으로 하고, 그 수단이 없으면 없다고 보고한다. 기억으로 때우지 마라.

## 두 델타 (deep-interview와의 관계)

정직하게 적는다. `deep-interview`는 이식된 별개 스킬로 있고, 이 스킬은 그 대체재가 아니라 **종료 기준과 질문 정책이 다른 별개 레인**이다.

| | deep-interview | ultra-interview |
|---|---|---|
| 종료 게이트 | 스칼라 자기채점 | **이산 체크리스트**의 미해결 비율 |
| 질문 정책 | 사람에게 묻는다 | **리서치가 답할 수 있는 건 묻지 않는다** |
| 리서치 | 질문을 선행 해소하지 않는다 | **선행한다** (E/I/P 판정 전에 돌린다) |

- `deep-interview --autoresearch`를 "리서치로 질문을 선행 해소"로 오해하지 마라. 그건 `autoresearch` 스킬로 넘기는 **셋업 레인**이고, 셋업을 위해 **오히려 질문을 더 던진다.** 이 스킬의 델타와 방향이 반대다.

## 계측: 이산 체크리스트

```
모호도 = 미해결 항목 수 / 전체 항목 수
종료   = 모호도 <= 0.03
```

**스칼라 자기채점을 쓰지 마라.** "명료도 0.95" 같은 자기 점수는 이 게이트에서 작동하지 않는다 — LLM 자기신뢰도 출력은 응답의 **78% 이상이 라운드넘버 3개(0.9/0.95/1.0)에 뭉치고**, 그 평균으로는 3%를 통과할 방법이 없다(통과하려면 어딘가에 1.0을 선언해야 한다). 스칼라 위의 3% 게이트는 결말이 둘뿐이다: 영원히 안 끝나거나, 점수를 부풀려 끝나거나.

**이건 셈이라 부풀릴 수 없다.** 항목은 열거되어 있고, 각 항목은 해결/미해결 둘 중 하나이며, 비율은 계산된다. 자기 자신에게 점수를 주는 행위가 아니므로 자기승인 금지 원칙과 충돌하지 않는다. 반대로 항목을 세지 않고 "대략 3% 정도"라고 말하는 순간, 그건 이름만 바꾼 스칼라 자기채점이다.

| 전체 항목 수 | 허용되는 미해결 수 | 산술 |
|---|---|---|
| 33 이하 | **0** | 1/33 = 3.0%를 넘김 |
| 34 ~ 66 | 1 | 1/34 = 2.9%로 3% 이하 |
| 67 이상 | 2 이상 | `floor(67 x 0.03)` = 2 |

일반형: 허용 미해결 수 = `floor(전체 항목 수 x 0.03)`. 항목이 33개 이하면 3%는 사실상 **"미해결 0개"**를 뜻한다. 34개 문턱을 넘기려고 항목을 쪼개 늘리지 마라 — 문턱은 목표가 아니라 산술의 결과다.

**항목의 조건:**
- **이진 판정 가능**해야 한다. "성능이 좋아야 한다"는 항목이 아니다. "p95 응답 목표치가 정해졌다"가 항목이다.
- **한 항목 한 사실.** 둘을 묶으면 반쪽 해결이 통째로 해결로 셈해진다.
- 항목은 0단계에서 뽑아 **고정**한다. 분모는 함부로 움직이는 값이 아니다.

## E/I/P 3분류 (질문 최소화 메커니즘)

전 항목을 셋 중 하나로 판정한다. **질문은 P에서만 나온다.**

| 분류 | 정의 | 처리 |
|---|---|---|
| **Evidence** | 공개 정보(공식 문서·법령·시행세칙·규칙·기록·best practice)가 답한다 | **묻지 않는다.** 리서치로 답하고 **근거 URL**을 단다 |
| **Inference** | 코드베이스·맥락에서 추론 가능하다 | **묻지 않는다.** 답하고 **추론임을 표시**한다 |
| **Preference** | 사람만 답할 수 있는 취향·제품 판단이다 | **이것만 질문한다** |

- E와 I로 답한 항목은 질문이 아니라 **"가정"으로 제시**한다. 사용자는 훑고 틀린 것만 집어내면 되므로 정정 비용이 답변 비용보다 싸다. 이게 질문을 줄이는 실제 메커니즘이다.
- **분류 오류의 대가가 비대칭이다.** P를 E로 잘못 밀면 사람의 판단을 리서치가 참칭한다. E를 P로 잘못 밀면 안 물어도 될 걸 물은 것뿐이다. **애매하면 P로 둔다.**
- 리서치가 답을 못 찾은 항목은 **P로 내려 질문**하고, 못 찾았다는 사실과 무엇을 찾아봤는지를 함께 적는다.
- **근거 URL 없는 E는 E가 아니다.** 기억으로 답해놓고 Evidence라고 표시하는 것이 이 스킬의 가장 위험한 실패다.

## 리서치 (선행)

**순서가 곧 설계다.** 리서치는 질문 **전에** 돌린다. 질문한 뒤에 리서치하면 이미 물어본 뒤라 아무것도 줄지 않는다.

범위: 최신 정보(요청에 걸린 기술·제품의 현재 상태) / 공식 문서(1차 출처) / 우수사례·best practice / 공개 규제 정보(규정·법령·시행세칙·규칙·기록).

**규제 정보 접근 규칙:**
- 엔드포인트·조회 파라미터·API 키를 하드코딩하지 마라. 지시는 일반형으로: **"해당 관할의 공식 1차 출처를 찾아라."**
- 1차 출처는 대개 그 규제를 **소관하는 기관의 공식 사이트**다. 블로그·요약글·2차 인용은 1차 출처가 아니다. **개정일·시행일을 함께 확인**한다.
- 1차 출처를 못 찾았으면 **찾았다고 하지 마라.** 그 항목은 P로 내린다.
- **규제 해석은 이 스킬의 산출물이 아니다.** 법적 판단이 필요한 자리는 P로 두고 사람에게 넘긴다.

**리서치 위임:** 이식된 deep-research 스킬이 있으면 "추가 질문 금지"를 인자에 명시하고 넘긴다. 명시하지 않으면 사용자가 리서치 단계에서 한 번, 인터뷰 단계에서 또 한 번 질문받아 스킬의 목적이 뒤집힌다. 넘기는 질문은 **이쪽에서 이미 좁혀서** 넘긴다 — 되물을 여지를 안 남기는 것이 인자에 적는 금지보다 확실하다. 미이식이면 browser.search로 직접 리서치한다.

## Workflow

### 0. 항목화 (분모 확정)

요청을 이진 판정 가능한 항목으로 펼친다. 항목은 요청의 **실제 표면**에서 뽑는다 — 개수를 맞추려고 만들지 않는다. 각 항목에 번호를 단다(이후 모든 절이 번호로 참조한다). 이 시점 전 항목 미해결, 모호도 = 1.00.

### 1. 리서치 선행

E 후보에 리서치를 돌린다. **질문 전이다.** 항목마다 근거 URL을 붙인다. URL 없는 답은 채택하지 않는다. 검색 수단이 런타임에 없으면 **없다고 보고**하고 E 후보를 전부 P로 내린 뒤 그 사실을 명시한다.

### 2. E/I/P 판정

전 항목을 분류한다. 애매하면 P. E는 근거 URL 첨부, I는 추론 근거(파일·경로·맥락) 첨부 + 추론 표시, P는 질문 목록으로.

### 3. 제시 (가정과 질문을 분리)

한 번에 낸다. 섞지 않는다.

```
가정 (틀린 것만 짚어주세요)
  #1  인증 = OAuth 2.0 authorization code + PKCE     [E] 근거: <공식 문서 url>
  #2  로그 보존 기간 = 소관 규정의 최소치            [E] 근거: <1차 출처 url + 시행일>
  #5  빌드 타깃 = 이 저장소의 기존 타깃과 동일       [I] 근거: <파일 경로>
  ... (E 9건 / I 4건 전문)

질문 (답이 필요합니다)
  #7  무료 등급에서도 이 기능을 여는가?              [P]
  #11 마이그레이션 중 다운타임을 허용하는가?         [P]

모호도 2/15 = 13.3%   (임계값 3%. 항목 15개라 3% 는 미해결 0개를 뜻함)
```

- 질문은 **P만**. 가정에 질문을 숨기지 마라. 가정은 전문을 낸다(발췌 금지). 가정은 사용자가 훑고 지나가도 되게 쓴다 — 한 줄이 한 사실이어야 훑을 수 있다.

### 4. 반영·재계측 (루프)

답과 정정을 항목에 반영하고 모호도를 **다시 센다.** 같은 질문을 다시 묻지 마라. 정정은 반박하지 말고 반영한다. 분모가 움직였으면 아래 절대 금지를 적용한다. 3 → 4를 임계값에 닿을 때까지 반복한다. **진전 없이 2회 돌면 멈추고 보고한다** — 남은 미해결 항목과 안 닫히는 이유를 적는다.

### 5. 검증 (보고 의무)

**"충분히 명확해졌다"는 판정을 쓰지 마라.** 판정은 **셈**으로만 한다.

```
전체 항목 : 15   (루프 중 추가 2, 삭제 0)
미해결    : 0
모호도    : 0/15 = 0.0%   (임계값 3%)
주의      : 항목 15개라 이 요청에서 3% 는 "미해결 0개" 를 뜻함
판정      : 통과
내역      : E 9 (URL 첨부) / I 4 (추론 표시) / P 2 (사용자 답변)
```

- 전체 항목 수와 미해결 수를 반드시 함께 낸다. 비율만 내면 검산이 안 된다.
- 루프 중 추가·삭제된 항목을 적는다. 미달로 멈췄으면 미달로 적는다. 가짜 통과 금지.
- E로 닫은 항목은 근거 URL을, I로 닫은 항목은 추론임을 최종 보고에도 남긴다.

## 절대 금지

1. **분모 조작.** 미해결 항목을 조용히 지우면 게이트가 무너진다. 삭제는 "이 요청 범위 밖"임을 명시·보고할 때만.
2. **가정만으로 통과 선언.** 사용자가 가정을 훑을 기회 1회를 거치기 전에는 판정하지 않는다.
3. **정량 과대선전.** "질문 N% 감소"는 측정한 적 없는 수치다. 약속은 하나: 리서치가 답할 수 있는 건 묻지 않는다. 파는 것은 질문 감소율이 아니라 질문의 종류다.
4. **표준 번호·저자로 권위 빌리기.** 미확인 인용은 검증 불가능한 권위다. 체크리스트만 실어라.
5. **리서치를 질문 뒤로 미루기.** 이미 물어본 뒤라 아무것도 줄지 않는다. 순서가 설계다.

## Output Contract

- 판정은 셈으로: 전체 항목 수, 미해결 수, 모호도, 추가·삭제 내역, E/I/P 내역.
- 미달이면 미달로 보고. 남은 항목 번호를 그대로 낸다.

## Operating Rules

- When to use: 모호한 채로 구현하면 되돌리기가 비싼 작업 / 공개 정보가 답할 수 있는 항목이 섞여 있을 때 / 사용자가 질문 세례를 원하지 않을 때.
- When NOT to use: 한 줄 수정·명백한 실행 / 요구사항 이미 확정 / 리서치가 닿지 않는 영역(비공개 사내 규정·미공개 스펙 — 전 항목이 Preference로 떨어져 그냥 인터뷰가 된다) / 취향만 물으면 되는 작업 / 리서치 자체가 목적일 때(deep-research 소관).
- 한계: 원본의 OMC/OMX 네이티브 인터뷰 채점(3차원/5차원) 참조는 Claude Code/Codex 런타임 전용이므로 축소한다. 이 스킬의 자체 루브릭(이산 체크리스트·3%)을 쓴다. 리서치 수단이 런타임에 없으면 없다고 보고한다.

ARGUMENTS: [--threshold <퍼센트>] [--no-research] [요청/맥락] (없으면 현재 작업의 요청에 적용)
- `--threshold`: 기본 3%. 올리면 게이트가 무르고, 내리는 것은 항목 33개 이하 구간에서 무의미하다(이미 미해결 0개가 조건). 바꾼 값을 보고에 적는다.
- `--no-research`: E 축이 죽어 전 항목이 P로 떨어지고 질문이 늘어난다. 켜서 부를 이유가 없으면 쓰지 마라.
