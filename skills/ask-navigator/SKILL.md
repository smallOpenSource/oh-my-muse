# ask-navigator: 항해사

## Purpose

- 목적지가 흐릿한(fog) 작업을 **결정 티켓의 지도**로 차트화하고, 프론티어 티켓을 세션당 하나씩 해소한다.
- 산출물은 **결정이지 산출물이 아니다**. 길이 열리면 빌드하지 않고 launch에 미션 브리프로 넘긴다.
- 역할 계약: captain(사용자)이 목적지(W1)와 차트(W2)에 서명한다. navigator는 captain이 답해야 할 질문에 절대 스스로 답하지 않는다.

## Workflow

### 1. Fog 테스트

두 질문 중 하나라도 "아니오"면 지도가 필요하다:
1. Q1 — 목적지를 한 문장으로 말할 수 있는가 (찾아내야 할 스펙·결정·변경)?
2. Q2 — 답은 못 해도 **처음 세 개의 결정**을 지금 정확히 말할 수 있는가?

둘 다 "예" → 지도 불필요, launch로 보낸다.

### 2. 지도 차트화 (차트 세션, 해소는 나중)

1. **감사, 연기**: drydock `--check` 감사를 보고 전용으로 실행 — 발견 사항은 지도의 Notes에 그대로 기록, 차트화는 막지 않는다.
2. **W1 — 목적지 서명**: deep-interview로 목적지(스펙·결정·변경)를 확정. 사용자에게 목적지 문장을 제시하고 **명시적 확인**을 받는다. 목적지를 못 정하면 후보를 순위 매겨 제시하거나 작업을 보류한다.
3. **프론티어 매핑**: deep-interview `--frontier`로 넓게 물어 전체 공간의 열린 결정을 끌어낸다. 지도가 이미 있으면 **Out of scope**를 먼저 읽는다 — 배제된 작업은 새 티켓이 되지 않는다. fog가 없으면 중단하고 launch 권장.
4. **W2 — 차트 서명**: 목적지·티켓(타입·블로킹 엣지)·fog 스케치를 제시하고 사용자가 서명할 때까지 반복.
5. **지도·티켓 생성**: 지도 이슈에 `navigator:map` 라벨, 티켓을 자식 이슈로, 블로킹 엣지는 2차 패스로 연결. 아직 선명하지 않은 것은 **Not yet specified**에 둔다.
6. **연구 티켓 발화**: `research` 티켓마다 `subagent.spawn` 백그라운드 서브에이전트를 병렬로 실행.
7. **종료**: 지도 링크 + 프론티어 티켓 수 + "다음 세션에 ask-navigator로 다음 결정을 진행하세요" 포인터.

### 3. 지도 진행 (세션당 티켓 하나)

1. **지도 로드**: 저해상도 뷰만, 티켓 본문은 필요 시 확대.
2. **선점**: 티켓을 captain에게 할당하거나 `Claimed-by` 기록 — 먼저 선점해야 동시 세션이 건너뛴다.
3. **타입별 해소** (아래 표 참조). captain 입력이 필요하면 deep-interview 호출.
4. **해소 기록**: 답변을 resolution 코멘트/섹션으로, 티켓 닫기, 지도 **Decisions so far**에 한 줄 요약 추가 — `[<티켓 제목>](링크): <한 줄 요약>`.
5. **프론티어 전진**: 선명해진 fog를 티켓으로 승격, 목적지를 벗어난 티켓은 닫고 **Out of scope**에 개념+사유 한 줄, 무효화된 티켓 정리.
6. **침전물(Sediment)**: 결정이 확정되는 즉시 — 용어는 CONTEXT.md 용어집, ADR급 결정은 `docs/adr/NNNN-<slug>.md`, 업무 규칙은 `docs/business/`. drydock 미실행 상태면 지도의 Notes `Deferred sediment`에 연기 기록.
7. **티켓 하나에서 중단**. 세션 종료 포인터: 방금 해소한 것과 현재 프론티어.

### 티켓 타입

모든 티켓은 **HITL**(captain과 함께, captain이 직접 말함) 또는 **AFK**(navigator 단독) 중 하나다. HITL 티켓은 라이브 교환으로만 해소된다 — 에이전트가 captain 역할을 대신하지 않는다.

| 타입 | 모드 | 해소 방법 |
|---|---|---|
| `research` | AFK | 백그라운드 서브에이전트가 1차 출처(공식 문서·소스 코드·스펙) 조사 → 결과를 티켓 코멘트(또는 답을 위해 아티팩트가 필요하면 머지하지 않는 throwaway 브랜치)에 기록, 티켓에 링크. 영구 리서치 파일은 만들지 않는다. 조사 결과는 해소하는 질문을 다시 진술하는 것으로 시작하고, 모든 주장에 출처를 링크하고, **Unverified** 섹션(확인 못한 것·그것이 중요한 이유)으로 끝낸다. 답이 사람에게 있으면 그 사람을 지목한 코멘트 하나로 묻기 (무작정 접촉 금지) |
| `loft` | HITL | loft 스킬 호출 — 버려도 되는 아티팩트로 captain 반응을 끌어내고 답에 접기 |
| `grilling` | HITL | deep-interview — 대화 자체가 해소, 기본 케이스 |
| `task` | HITL/AFK | 결정을 푸는 데 필요한 수동 작업만 (접근 권한, 데이터 이동). 결정을 푸는 것으로 존재 이유를 증명해야지 목적지를 전달하는 것으로는 안 된다 |

### 지도 본문 구조

```markdown
## Destination
<목적지 1-2줄>
## Notes
<도메인, 매 세션 참고할 스킬, 연기된 drydock 발견(그대로), documentLanguage 태그>
## Decisions so far
- [<닫힌 티켓 제목>](링크): <한 줄 요약>
## Not yet specified
<티켓으로 못 낼 만큼 흐릿한 in-scope fog>
## Out of scope
<목적지 밖으로 판정된 작업 — 돌아오지 않음>
```

**Fog vs 티켓**: 답할 수 있느냐가 아니라 질문을 지금 정확히 말할 수 있느냐로 판단. 날카로우면 티켓, 흐릿하면 Not yet specified. fog를 미리 티켓 크기로 자르지 않는다 — 하나의 fog 패치는 나중에 여러 티켓이 되거나, 하나도 안 될 수 있다. **Out of scope**는 경로상의 단계가 아니라 스코프 행위다: 스코프가 작업자를 보내지 날카로움이 보내지 않는다. launch의 C3 수직 슬라이스 빌드 티켓으로 fog를 미리 자르지도 않는다.

**지도는 인덱스지 저장소가 아니다**: 결정은 정확히 한 곳(그 티켓)에 산다. 지도는 한 줄 요약+링크로 가리킬 뿐, 상세를 다시 쓰지 않는다.

### 큰 작업 — 지도가 세션을 넘어 산다

차트화 결과 프론티어가 세션 몇 개로 정리될 규모가 아닐 때 (여러 독립 스레드, 계속 열리는 fog) 지도는 장기 생존형이 된다:

- **Vessel**: 프론티어의 독립 스레드를 vessel로 명명해 Notes에 기록. 세션은 전체 공간을 다시 읽지 않고 한 스레드에 정위할 수 있다.
- **Census line**: vessel별 오픈 티켓 수와 현재 프론티어를 한 줄로, 세션마다 새로고침. 지도만 읽은 세션도 작업 상태를 알 수 있다.
- 세션당 티켓 하나의 예산은 vessel 우선순위 순으로 프론티어에 쓴다 — 리듬은 바뀌지 않고 지평만 넓어진다.

### 종료 — 넘기고 빌드하지 않는다

오픈 티켓이 없고 Not yet specified가 비면:
1. **Decisions so far**를 **미션 브리프**(목적·범위 경계·non-goals)로 접어 `.omc/wayfinder/<map-slug>/brief.md`에 저장 — 내용 전달이 아니라 포인터 전달.
2. 권장: "길이 열렸습니다. `.omc/wayfinder/<map-slug>/brief.md` 브리프와 함께 launch를 실행하세요."
3. 기본 진입은 launch Phase 1.

## Output Contract

- 차트 세션: 사용자 서명된 지도 + 발화된 research 티켓.
- 진행 세션: 티켓 하나 해소 기록 + 전진된 프론티어 + 세션 종료 포인터.
- 종료: 미션 브리프 파일 경로 + launch 권장.

## Operating Rules

- 한계: 원본의 트래커(GitHub/GitLab) 연동은 `gh`/`glab` CLI가 있을 때만 가능. 없으면 로컬 마크다운 모드(`.omc/wayfinder/<map-slug>/map.md` + `decisions/NN-<slug>.md`)로 진행, Notes에 단일 드라이버 관례 명시. 경로는 레포 루트 상대.
- 서브에이전트: 원본의 Task tool 병렬 실행 → `subagent.spawn`.
- 슬래시 커맨드(`/oh-my-claudecode:launch` 등)는 채팅 트리거로 대체 — "launch를 실행해줘".
- 절대 새로 지어내지 말 것: 트래커에 없는 이슈 번호·라벨·티켓 링크를 꾸며내지 않는다. Not yet specified의 fog를 티켓 크기로 미리 자르지 않는다.
- 역할 계약 위반 금지: captain의 결정에 대리 답변 금지.
- harbor가 넘긴 fuzzy 이슈도 차트 대상이다 — 원래 스레드와 서명된 결정 링크를 소재로 쓰고 다른 느슨한 아이디어처럼 차트화한다.
