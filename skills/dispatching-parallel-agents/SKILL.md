# 병렬 에이전트 파견

## 개요

격리된 컨텍스트의 전문 에이전트에게 위임한다. 지시와 컨텍스트를 정밀하게
만들어 집중하고 성공하게 한다. 내 세션의 컨텍스트·히스토리를 물려주지 않는다 —
필요한 것만 구성한다. 내 컨텍스트는 조정 작업용으로 보존한다.

관련 없는 실패가 여러 개면(다른 테스트 파일, 다른 하위 시스템, 다른 버그)
순차 조사는 시간 낭비다. 각 조사는 독립적이고 병렬로 진행할 수 있다.

**핵심 원칙:** 독립된 문제 영역마다 에이전트 하나. 동시에 일하게 한다.

**[환경 한계]** 이 서브에이전트 환경에서는 직접 서브에이전트를 파견할 수 없다.
병렬 파견이 필요한 단계는 상위 에이전트에게 위임 요청한다 — 독립 작업 목록과
각 작업의 프롬프트를 보고서에 담아 전달한다.

## 사용 시점

**사용할 때:**
- 서로 다른 근본 원인의 3개 이상 테스트 파일 실패
- 독립적으로 깨진 여러 하위 시스템
- 다른 것의 맥락 없이 이해 가능한 각 문제
- 조사 간 공유 상태 없음

**사용하지 않을 때:**
- 실패가 관련 있다 (하나를 고치면 다른 것도 고쳐질 수 있음) — 먼저 함께 조사
- 전체 시스템 상태를 이해해야 함
- 에이전트끼리 간섭 (같은 파일 편집, 같은 자원 사용)

## 패턴

### 1. 독립 영역 식별

깨진 것 기준으로 실패를 그룹화한다:
- 파일 A 테스트: 도구 승인 흐름
- 파일 B 테스트: 배치 완료 동작
- 파일 C 테스트: 중단 기능

각 영역은 독립적이다 — 도구 승인을 고쳐도 중단 테스트에 영향 없다.

### 2. 집중된 에이전트 작업 만들기

각 에이전트에게 주는 것:
- **구체적 범위:** 테스트 파일 하나 또는 하위 시스템 하나
- **명확한 목표:** 이 테스트들을 통과시켜라
- **제약:** 다른 코드는 바꾸지 마라
- **기대 출력:** 무엇을 찾고 고쳤는지 요약

### 3. 병렬 파견

같은 응답에 모든 파견 호출을 함께 발행 — 병렬로 실행된다. 한 응답에 하나씩이면 순차다.

### 4. 리뷰와 통합

에이전트가 돌아오면:
- 각 요약을 읽는다
- 수정이 충돌하지 않는지 검증한다
- 전체 테스트 스위트를 실행한다
- 모든 변경을 통합한다

## 에이전트 프롬프트 구조

좋은 에이전트 프롬프트는:
1. **집중** — 하나의 명확한 문제 영역
2. **자립** — 문제를 이해하는 데 필요한 모든 맥락
3. **출력 명시** — 에이전트가 무엇을 돌려줄 것인가

```markdown
src/agents/agent-tool-abort.test.ts의 실패 3개를 고쳐라:

1. "should abort tool with partial output capture" - 메시지에서 'interrupted at' 기대
2. "should handle mixed completed and aborted tools" - 빠른 도구가 완료 대신 중단됨
3. "should properly track pendingToolCount" - 결과 3개 기대, 0개 받음

타이밍/레이스 이슈. 작업:

1. 테스트 파일을 읽고 각 테스트가 검증하는 것을 이해
2. 근본 원인 파악 - 타이밍 이슈인가 실제 버그인가
3. 수정:
   - 임의 타임아웃을 이벤트 기반 대기로 교체
   - 중단 구현의 버그를 찾으면 수정
   - 변경된 동작을 테스트 중이면 테스트 기대값 조정

타임아웃만 늘리지 마라 - 실제 이슈를 찾아라.

반환: 근본 원인과 변경 내용 요약.
```

## 흔한 실수

**❌ 너무 넓다:** "모든 테스트 고쳐" — 에이전트가 길을 잃는다
**✅ 구체적:** "agent-tool-abort.test.ts 고쳐" — 집중된 범위

**❌ 맥락 없음:** "레이스 컨디션 고쳐" — 어디인지 모른다
**✅ 맥락:** 에러 메시지와 테스트 이름을 붙여준다

**❌ 제약 없음:** 에이전트가 전부 리팩터할 수 있다
**✅ 제약:** "프로덕션 코드는 바꾸지 마라" 또는 "테스트만 고쳐라"

**❌ 모호한 출력:** "고쳐" — 무엇이 바뀌었는지 모른다
**✅ 구체적:** "근본 원인과 변경 요약 반환"

## 검증

에이전트가 돌아온 뒤:
1. **각 요약 리뷰** — 무엇이 바뀌었는지 이해
2. **충돌 확인** — 같은 코드를 편집했는가?
3. **전체 스위트 실행** — 모든 수정이 함께 동작하는지 검증
4. **표본 점검** — 에이전트도 체계적 실수를 할 수 있다
