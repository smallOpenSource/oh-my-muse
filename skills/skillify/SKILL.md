# Skillify

## Purpose

현재 세션에서 드러난 반복 가능한 워크플로를 나중에 다시 발견하지 않도록 구체적인 스킬 초안으로 포착한다.

## Workflow

1. 세션이 실제로 수행한 반복 가능한 작업을 식별한다.
2. 다음을 추출한다: 입력, 순서화된 단계, 성공 기준, 제약/함정, 검증 증거, 스킬의 최적 저장 위치.
3. **품질 게이트** — 세 가지가 모두 참이어야 추출한다:
   - "이걸 5분 안에 검색으로 찾을 수 있는가?" → 아니오.
   - "이 코드베이스/프로젝트/워크플로에 특화된 것인가?" → 예.
   - "발견에 실제 디버깅·설계·운영 노력이 들었는가?" → 예.
   - 결정 휴리스틱·제약·함정·검증 단계를 담은 스킬을 선호. 일반 스니펫·보일러플레이트·라이브러리 사용 예시는 제외한다.
4. 초안을 완전한 스킬 파일로 작성한다. **반드시 YAML 프론트매터로 시작**하며, 마크다운만 있는 파일은 금지한다. 최소 프론트매터:

   ```yaml
   ---
   name: <skill-name>
   description: <한 줄 설명 — 트리거 문구 포함>
   triggers:
     - <trigger-1>
     - <trigger-2>
   ---
   ```

5. 이 환경의 저장 위치는 단일 스코프다: `~/workspace/skills/<skill-name>/SKILL.md`. 원본의 `${CLAUDE_CONFIG_DIR}/skills/omc-learned/`, `.omc/skills/` 경로는 이 환경에 없으므로 사용하지 않는다.
6. 본문은 이 환경의 표준 구조(Purpose / Workflow / Output Contract / Operating Rules)를 따른다.
7. 아직 안전하게 인코딩하기엔 모호한 부분은 초안에 "미확정"으로 명시한다.

## Output Contract

- 제안된 스킬 이름
- 저장 위치(`~/workspace/skills/<이름>/SKILL.md`)
- 초안 스킬 파일(프론트매터 포함 완성본) 또는 구조 제안
- 품질 게이트 통과 근거
- 미해결 질문(있으면)

## Operating Rules

- 실제로 반복 가능한 워크플로만 포착한다. 한 번성 작업은 스킬로 만들지 않는다.
- 원본의 "repo built-in vs user/project learned" 구분은 이 환경에 없다 — 저장소는 `~/workspace/skills/` 단일이다.
- 워크플로에 아직 해소되지 않은 분기 결정이 있으면 초안을 쓰기 전에 명시한다.
- 모호한 성공 기준보다 명시적인 성공 기준을 선호한다.
